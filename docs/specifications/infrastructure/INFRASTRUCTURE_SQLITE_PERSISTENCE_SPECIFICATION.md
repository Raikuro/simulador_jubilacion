# SQLite Persistence Specification

**Document Type:** Behavioral Specification (Frozen)  
**Status:** APPROVED & FROZEN  
**Milestone:** v0.4 Infrastructure & Deployment  
**Responsibility:** Define the complete data persistence contract for SQLite storage  

---

## 1. Purpose

This specification defines the **complete and exact behavior** of the SQLite persistence layer. It serves as the contract between the domain layer and infrastructure, ensuring:

- Domain objects persist and retrieve **without loss of information**
- Schema design supports all required queries
- Transaction semantics guarantee consistency
- Migration path defined for future versions

## 2. Persistence Scope

### 2.1 What Gets Persisted

| Entity | Persist? | Identity | Format |
|--------|----------|----------|--------|
| **ExperimentDefinition** | ✅ YES | Natural: (study_name, version) | Normalized (1 record + relationships) |
| **ResearchPlan** | ✅ YES | Natural: (plan_id) | Normalized (Plan + 1-to-many PlannedUnits) |
| **PlannedSimulationUnit** | ✅ YES | Composite: (plan_id, cohort_start_date, param_config_id) | Normalized fact record |
| **CohortSpecification** | ✅ YES (via reference) | Natural: (start_date) | Foreign key to ExperimentDefinition |
| **ParameterConfiguration** | ✅ YES | Natural: (name, params_hash) | Key-value pairs in JSON |
| **AllocationPolicy** | ✅ YES | Composite: (policy_type, parameter_set) | Policy type + parameter JSON |
| **WithdrawalPolicy** | ✅ YES | Composite: (policy_type, parameter_set) | Policy type + parameter JSON |
| **ResearchExecutionResult** | ✅ YES | Natural: (plan_id) | Normalized (Result metadata + SimulationResults) |
| **SimulationResult** | ✅ YES | Composite: (plan_id, unit_index, year, month) | Monthly fact table |
| **Portfolio** (terminal) | ✅ YES (terminal only) | Via SimulationResult | Denormalized in result record |
| **MonthlyResult** | ✅ YES | Composite: (plan_id, unit_index, month_index) | Monthly fact table |

### 2.2 What Does NOT Get Persisted

| Entity | Reason |
|--------|--------|
| **MarketDataset** | Loaded from external source; not generated by framework |
| **Policy Instances** (in memory) | Serialized as (type, parameters), not object instances |
| **SimulationRunner** | Stateless execution service; no state to persist |
| **ResearchExecutor** | Stateless orchestrator; no state to persist |

## 3. Schema Design

### 3.1 Core Tables

#### Table: `experiments`

```sql
CREATE TABLE experiments (
    experiment_id          TEXT PRIMARY KEY,
    name                   TEXT NOT NULL UNIQUE,
    version                TEXT NOT NULL,
    dataset_identifier     TEXT NOT NULL,     -- e.g., "ACWI_EUR_2024"
    start_year            INTEGER,
    end_year              INTEGER,
    horizon_years         INTEGER,            -- 30, 40, 50
    created_at            TIMESTAMP NOT NULL,
    updated_at            TIMESTAMP NOT NULL,
    description           TEXT,
    
    UNIQUE(name, version)
);
```

#### Table: `cohorts` (Linked to Experiments)

```sql
CREATE TABLE cohorts (
    cohort_id             TEXT PRIMARY KEY,
    experiment_id         TEXT NOT NULL REFERENCES experiments(experiment_id),
    start_date            TEXT NOT NULL,     -- YYYY-MM-DD format
    end_date              TEXT,               -- May be NULL for open-ended
    cohort_type           TEXT,               -- "monthly_rolling", "fixed_horizon", "stress_test"
    created_at            TIMESTAMP NOT NULL,
    
    UNIQUE(experiment_id, start_date),
    INDEX idx_cohort_dates(experiment_id, start_date)
);
```

#### Table: `parameter_configurations`

```sql
CREATE TABLE parameter_configurations (
    param_config_id       TEXT PRIMARY KEY,
    name                  TEXT NOT NULL,
    params_json           TEXT NOT NULL,     -- JSON: {"equity_allocation": "0.75", ...}
    params_hash           TEXT NOT NULL,     -- SHA256(params_json) for uniqueness
    created_at            TIMESTAMP NOT NULL,
    
    UNIQUE(params_hash)
);
```

#### Table: `policies`

```sql
CREATE TABLE policies (
    policy_id             TEXT PRIMARY KEY,
    policy_type           TEXT NOT NULL,     -- e.g., "ConstantAllocationPolicy"
    params_json           TEXT NOT NULL,     -- {"equity_allocation": "0.75"}
    params_hash           TEXT NOT NULL,     -- SHA256(params_json)
    created_at            TIMESTAMP NOT NULL,
    
    UNIQUE(policy_type, params_hash),
    INDEX idx_policy_type(policy_type)
);
```

#### Table: `research_plans`

```sql
CREATE TABLE research_plans (
    plan_id               TEXT PRIMARY KEY,
    experiment_id         TEXT NOT NULL REFERENCES experiments(experiment_id),
    created_at            TIMESTAMP NOT NULL,
    unit_count            INTEGER NOT NULL,
    status                TEXT NOT NULL,     -- "planned", "executing", "completed", "failed"
    
    INDEX idx_plan_experiment(experiment_id)
);
```

#### Table: `planned_units`

```sql
CREATE TABLE planned_units (
    unit_id               TEXT PRIMARY KEY,
    plan_id               TEXT NOT NULL REFERENCES research_plans(plan_id),
    unit_index            INTEGER NOT NULL,   -- 0-based position in plan
    cohort_id             TEXT NOT NULL REFERENCES cohorts(cohort_id),
    param_config_id       TEXT NOT NULL REFERENCES parameter_configurations(param_config_id),
    allocation_policy_id  TEXT NOT NULL REFERENCES policies(policy_id),
    withdrawal_policy_id  TEXT NOT NULL REFERENCES policies(policy_id),
    initial_portfolio_json TEXT NOT NULL,    -- Frozen initial state
    
    UNIQUE(plan_id, unit_index),
    UNIQUE(plan_id, cohort_id, param_config_id),
    INDEX idx_unit_plan(plan_id)
);
```

#### Table: `execution_results`

```sql
CREATE TABLE execution_results (
    result_id             TEXT PRIMARY KEY,
    plan_id               TEXT NOT NULL REFERENCES research_plans(plan_id),
    executed_at           TIMESTAMP NOT NULL,
    duration_seconds      REAL NOT NULL,
    success_count         INTEGER NOT NULL,
    failure_count         INTEGER NOT NULL,
    total_units           INTEGER NOT NULL,
    
    UNIQUE(plan_id),
    INDEX idx_result_plan(plan_id)
);
```

#### Table: `simulation_results`

```sql
CREATE TABLE simulation_results (
    result_id             TEXT PRIMARY KEY,
    execution_result_id   TEXT NOT NULL REFERENCES execution_results(result_id),
    unit_index            INTEGER NOT NULL,  -- Index in plan (0-based)
    month_index           INTEGER NOT NULL,  -- Index in timeline (0-based)
    portfolio_value       TEXT NOT NULL,     -- Decimal as string (e.g., "500000.00")
    equity_value          TEXT NOT NULL,
    bond_value            TEXT NOT NULL,
    cash_value            TEXT NOT NULL,
    monthly_return        TEXT NOT NULL,     -- Decimal as string
    allocation_ratio      TEXT,               -- JSON: {"equity": "0.75", "bond": "0.25"}
    withdrawal_amount     TEXT NOT NULL,
    final_portfolio       INTEGER,            -- 1 if final month, 0 otherwise
    
    UNIQUE(execution_result_id, unit_index, month_index),
    INDEX idx_results_execution(execution_result_id),
    INDEX idx_results_unit_month(unit_index, month_index)
);
```

### 3.2 Schema Invariants

| Constraint | Rule | Enforcement |
|-----------|------|-------------|
| **Referential Integrity** | All foreign keys enforced | `PRAGMA foreign_keys = ON` |
| **Uniqueness** | No duplicate cohorts per experiment | UNIQUE constraint on (experiment_id, start_date) |
| **Uniqueness** | No duplicate parameter configs | UNIQUE constraint on params_hash |
| **Uniqueness** | No duplicate units in plan | UNIQUE constraint on (plan_id, unit_index) |
| **Completeness** | Every execution_result linked to plan | Foreign key constraint |
| **Ordering** | Units preserve insertion order | unit_index field |
| **Temporal** | All timestamps in UTC | Application layer enforces |

## 4. Serialization Contracts

### 4.1 Decimal Serialization

**Rule:** All financial values stored as **strings** to avoid floating-point precision loss.

```python
# ✅ CORRECT
portfolio_value = "500000.00"

# ❌ INCORRECT: Do not store as float
portfolio_value = 500000.00
portfolio_value = 500000
```

**Implementation:**

```python
from decimal import Decimal

def serialize_decimal(value: Decimal) -> str:
    """Convert Decimal to string preserving full precision."""
    return str(value)

def deserialize_decimal(value: str) -> Decimal:
    """Convert string to Decimal."""
    return Decimal(value)
```

### 4.2 JSON Serialization (Policies & Parameters)

**Rule:** Policy parameters and parameter configurations stored as JSON for human readability and querying.

```json
{
  "equity_allocation": "0.75",
  "bond_allocation": "0.20",
  "cash_allocation": "0.05"
}
```

**Implementation:**

```python
from dataclasses import asdict
import json

def serialize_policy_params(policy: AllocationPolicy) -> str:
    """Convert policy to JSON string."""
    params = {
        "equity_allocation": str(policy.equity_allocation),
        "bond_allocation": str(policy.bond_allocation),
        # ... other fields
    }
    return json.dumps(params, sort_keys=True)

def deserialize_policy_params(json_str: str) -> Dict[str, str]:
    """Parse JSON into dict."""
    return json.loads(json_str)
```

### 4.3 Date Serialization

**Rule:** Dates stored as ISO 8601 strings (YYYY-MM-DD format).

```python
# ✅ CORRECT
start_date = "2020-01-01"

# ❌ INCORRECT: Do not store as timestamps
start_date = 1577836800

# ❌ INCORRECT: Do not use other formats
start_date = "01/01/2020"
```

## 5. Transaction Semantics

### 5.1 Isolation Level

**Rule:** Use SQLite's default `DEFERRED` transaction mode.

```python
# Application pattern:
with sqlite_conn:
    cursor.execute("INSERT INTO experiments ...")
    cursor.execute("INSERT INTO cohorts ...")
    # Auto-commit on successful exit, auto-rollback on exception
```

### 5.2 Write Concurrency

**Constraint:** SQLite allows only one writer at a time.

**Implications:**
- Parallel readers: ✅ Supported (multiple processes)
- Parallel writers: ❌ Not supported (will raise `sqlite3.OperationalError`)
- Solution: Serialize writes; parallelize reads

### 5.3 Durability Guarantee

**Rule:** After commit, data persists even if process crashes.

```python
# Ensure durability:
PRAGMA journal_mode = WAL;   # Write-Ahead Logging
PRAGMA synchronous = NORMAL;  # Faster than FULL but still safe
```

## 6. Data Loading & Query Patterns

### 6.1 Load Experiment Definition

```sql
SELECT 
    e.experiment_id,
    e.name,
    e.version,
    e.dataset_identifier,
    json_extract(e.metadata, '$.start_year') as start_year,
    json_extract(e.metadata, '$.end_year') as end_year
FROM experiments e
WHERE e.name = ? AND e.version = ?;
```

### 6.2 Load Research Plan with Units

```sql
SELECT 
    rp.plan_id,
    rp.created_at,
    pu.unit_index,
    pu.cohort_id,
    c.start_date,
    pu.param_config_id,
    pc.params_json,
    ap.policy_type as allocation_policy_type,
    ap.params_json as allocation_params,
    wp.policy_type as withdrawal_policy_type,
    wp.params_json as withdrawal_params
FROM research_plans rp
JOIN planned_units pu ON rp.plan_id = pu.plan_id
JOIN cohorts c ON pu.cohort_id = c.cohort_id
JOIN parameter_configurations pc ON pu.param_config_id = pc.param_config_id
JOIN policies ap ON pu.allocation_policy_id = ap.policy_id
JOIN policies wp ON pu.withdrawal_policy_id = wp.policy_id
WHERE rp.plan_id = ?
ORDER BY pu.unit_index ASC;
```

### 6.3 Load Execution Results

```sql
SELECT 
    sr.unit_index,
    sr.month_index,
    sr.portfolio_value,
    sr.equity_value,
    sr.bond_value,
    sr.cash_value,
    sr.monthly_return,
    sr.allocation_ratio,
    sr.withdrawal_amount
FROM simulation_results sr
WHERE sr.execution_result_id = ?
ORDER BY sr.unit_index ASC, sr.month_index ASC;
```

## 7. Lossless Round-Trip Verification

### 7.1 Verification Test Pattern

Every serialization must satisfy:

```python
# Given: domain object
original = ExperimentDefinition(
    name="SWR Part 19",
    start_year=1871,
    # ... other fields
)

# When: persist and retrieve
stored_id = repository.save_study(original)
retrieved = repository.load_study(stored_id)

# Then: original ≡ retrieved (field by field)
assert original.name == retrieved.name
assert original.start_year == retrieved.start_year
# ... all fields verified
```

- [ ] Round-trip: All date values preserved exactly

## 9. Error Handling

### 9.1 Persistence Errors

| Error | Cause | Action |
|-------|-------|--------|
| `sqlite3.IntegrityError` | Duplicate key or foreign key violation | Wrap in `RepositoryError`; provide context |
| `sqlite3.OperationalError` | Database locked (concurrent writes) | Retry with exponential backoff (max 5 retries) |
| `sqlite3.OperationalError` | Disk full | Raise `PersistenceError` with clear message |
| `sqlite3.DatabaseError` | Corrupted database | Raise `CorruptedDatabaseError`; recommend backup recovery |

### 9.2 Exception Hierarchy

```python
class RepositoryError(Exception):
    """Base class for persistence errors."""
    pass

class StudyNotFoundError(RepositoryError):
    """Requested study ID not in database."""
    pass

class ResultsNotFoundError(RepositoryError):
    """Results for study not persisted."""
    pass

class DuplicateStudyError(RepositoryError):
    """Study with same name/version already exists."""
    pass

class PersistenceError(RepositoryError):
    """General persistence failure (I/O, disk full, etc.)."""
    pass

class CorruptedDatabaseError(RepositoryError):
    """Database file corrupted."""
    pass
```

## 10. Performance Considerations

### 10.1 Indexing Strategy

| Query Pattern | Index | Rationale |
|---------------|-------|-----------|
| Find experiment by name | `(name, version)` | Frequent CLI queries |
| List cohorts for experiment | `(experiment_id, start_date)` | Plan construction queries |
| Find results by plan | `(plan_id)` | Single-row lookup |
| Query results by time | `(execution_result_id, unit_index, month_index)` | Result analysis queries |

### 10.2 Query Optimization

**Rule:** Always ORDER BY explicitly; don't rely on table scan order.

```python
# ✅ CORRECT
SELECT * FROM planned_units WHERE plan_id = ? ORDER BY unit_index ASC;

# ❌ INCORRECT: Order not guaranteed
SELECT * FROM planned_units WHERE plan_id = ?;
```
