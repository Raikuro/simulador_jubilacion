## Implementation Phases (Sequential)

### Phase 1: Parallel Execution Engine ⭐ START HERE

**Responsibility:** Implement multi-core execution with ProcessPoolExecutor.

**Specification:** `PARALLEL_EXECUTION_SPECIFICATION.md`

**Architectural Rationale for Phase Ordering:**

Phase 1 must be Parallel Execution (not Persistence) because:

1. **No External Dependencies** — Pure algorithmic work; can be tested in complete isolation without database or I/O
2. **Concrete Data Model** — After Phase 1, we know exactly what execution data exists and must be persisted
3. **Risk Reduction** — Test hard algorithmic concerns (determinism, batching, error isolation) before adding I/O complexity
4. **Schema Design Dependency** — SQLite schema (Phase 2) should be designed based on actual execution data, not speculation
5. **Dependency Graph:** Phase 2 depends on understanding Phase 1 output; Phase 1 depends on nothing

**Dependency Flow:**
```
Phase 1 (Parallel)        [independent]
    ↓ (generates data structures)
Phase 2 (Persistence)     [persists Phase 1 data]
    ↓ (provides storage API)
Phase 3 (CLI)             [uses both Phase 1 & 2]
    ↓ (integrates)
Phase 4 (Integration)     [tests everything]
```

**Deliverables:**
- [ ] ParallelExecutor class implemented
- [ ] Deterministic work batching implemented
- [ ] Result collection in order implemented
- [ ] Error isolation implemented
- [ ] Progress tracking implemented
- [ ] Determinism verified

**Exit Criteria:**
- Parallel results ≡ sequential results (bit-for-bit identical)
- Determinism maintained across multiple runs
- One worker failure doesn't stop others
- Memory usage bounded
- Performance acceptable (speedup ≥ 0.8 × worker count)

**Success Verification:**

## Critical Constraints (Non-Negotiable)

### 1. Domain Layer Unchanged

✅ **MUST:** All domain code (v0.1, v0.2.3, v0.3) remains unchanged.

❌ **MUST NOT:** Modify any domain objects, policies, or services.

**Why:** Changing domain logic while adding infrastructure conflates two independent concerns and risks breaking frozen contracts.

**Verification:** All existing domain tests must pass unchanged.

### 2. Clean Architecture Boundaries

✅ **MUST:** Infrastructure layer has zero knowledge of domain business logic.

✅ **MUST:** Infrastructure depends on frozen public APIs (not internal implementation).

❌ **MUST NOT:** Add dependencies to domain layer.

**Architecture Rule:**
```
CLI → Research → Engine → Infrastructure (external)
↑                          ↑
│ (GOOD: depends down)     │ (BAD: never inward)
└──────────────────────────┘
```

### 3. Determinism Guarantee

✅ **MUST:** Parallel execution produces identical results to sequential.

✅ **MUST:** Same plan + same configuration → same results (always).

❌ **MUST NOT:** Introduce non-determinism in work assignment or result ordering.

**Verification Test:**
```python
seq_result = sequential_execute(plan)
par_result = parallel_execute(plan, workers=4)
assert seq_result == par_result  # Must pass every time
```

### 4. Immutability Preserved

✅ **MUST:** All domain objects remain frozen dataclasses.

✅ **MUST:** Serialization logic entirely in infrastructure layer.

❌ **MUST NOT:** Create mutable wrappers or ORM decorators on domain objects.

**Example (✅ Correct):**
```python
@dataclass(frozen=True)
class AllocationPolicy:
    equity_allocation: Decimal

# Adapter in infrastructure only
class PolicySQLiteAdapter:
    def serialize(policy: AllocationPolicy) -> str
    def deserialize(json_str: str) -> AllocationPolicy
```

**Example (❌ Wrong):**
```python
# WRONG: Don't do this
@dataclass
class AllocationPolicy(SQLAlchemy):
    __tablename__ = "policies"
    equity_allocation = Column(Decimal)
```

### 5. Specification Compliance

✅ **MUST:** Implement specifications exactly as written.

✅ **MUST:** All acceptance criteria met.

❌ **MUST NOT:** Deviation from specifications without architect approval.

**If Ambiguity Found:**
- Stop implementation
- Document the ambiguity
- Request clarification from architect
- Resume only after clarification frozen in specification
