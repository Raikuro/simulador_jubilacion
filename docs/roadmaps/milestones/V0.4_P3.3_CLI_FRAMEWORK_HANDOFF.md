## Executive Summary

P3.3 is the third implementation package of Phase 3. It establishes the **CLI entry point and command framework** that all subsequent CLI command packages (P3.4–P3.9) will plug into.

This package provides:
1. **`sim-retire` console script** — registered in `pyproject.toml`, invocable from the shell.
2. **Root argument parser** — `argparse`-based, with shared global options (`--version`, `--help`, `--verbose`, `--debug`, `--data-dir`).
3. **Command registration mechanism** — an explicit, deterministic registry (`COMMANDS` dict) that maps command names to `BaseCommand` subclasses. No auto-discovery or decorators.
4. **`BaseCommand` abstract class** — defines the contract every command must satisfy: a `name`, `help_text`, and an `execute(context, args)` method.
5. **`ExecutionContext` value object** — a lightweight dataclass carrying only globally-scoped CLI environment information (verbosity, debug mode, data directory). No persistence services, no application services.
6. **Exit code convention** — `0` success, `1` execution error, `2` validation error, `130` interrupted.
7. **Error handling** — consistent error formatting, `KeyboardInterrupt` handling producing exit code 130.

P3.3 implements **no specific CLI commands**. Each command (`validate`, `run`, `list`, `export`, `optimize`, `compare`) is a separate downstream package starting with P3.4.

---

## Architectural Constraints

- **No frozen domain changes.** No `engine.*`, `research.*`, or `infrastructure.persistence.*` files are modified.
- **No application orchestration.** The CLI framework does not import or invoke `study_runner`, `optimization_runner`, `comparison_runner`, or any application-layer code.
- **`argparse` only (stdlib).** No `click`, `typer`, or third-party CLI libraries. The framework must have zero external dependencies.
- **Explicit command registry.** No automatic discovery, no decorators, no metaclass magic — a plain `COMMANDS` dict is sufficient.
- **`ExecutionContext` stays lightweight.** It contains only environment context (verbose, debug, data_dir). It must not eagerly create or hold `PersistenceReconstructionContext`, repositories, or application services.
- **Exit codes match the frozen CLI specification** (`CLI_INTERFACE_SPECIFICATION.md`).
- **No output formatters or file I/O.** Table formatting, CSV/JSON export, and config file loading are deferred to later packages.

## What Must Exist

### 1. `pyproject.toml` console script

Add a `[project.scripts]` entry:

```toml
[project.scripts]
sim-retire = "cli.main:main"
```

The `cli` package already exists at `src/cli/` (skeleton with `__init__.py` and a stub `main()`).

### 2. `src/cli/` package layout

```
src/cli/
├── __init__.py              # Exports main, BaseCommand, ExecutionContext
├── main.py                  # main() entry point, root parser, dispatch
├── commands/
│   ├── __init__.py          # COMMANDS registry dict
│   └── base.py              # BaseCommand abstract class
└── error_handling.py        # ExitCode enum, format_error(), handle_exception()
```

The existing `main.py` stub (empty `main()`) is replaced with the real implementation.

### 3. Root CLI parser (`main.py`)

An `argparse.ArgumentParser` configured as:

| Option | Action | Dest | Default | Help |
|--------|--------|------|---------|------|
| `--version` | `store_true` | `version` | `False` | Print version and exit |
| `--verbose` | `store_true` | `verbose` | `False` | Enable verbose output |
| `--debug` | `store_true` | `debug` | `False` | Enable debug logging |
| `--data-dir` | `store` | `data_dir` | `None` | Path to dataset directory |

The parser uses `add_subparsers()` for command registration. When a subcommand is registered, its help is automatically included in the root `--help` output.

**Required behavior:**
- `sim-retire --help` prints usage, global options, and lists registered commands.
- `sim-retire --version` prints the package version from `importlib.metadata` and exits 0.
- `sim-retire` with no arguments prints help and exits 0.
- `sim-retire UNKNOWN_COMMAND` prints an error message and exits 2.

### 4. Command registry (`commands/__init__.py`)

A single module-level dict:

```python
COMMANDS: dict[str, type[BaseCommand]] = {}
```

Registration is explicit and manual:

```python
from cli.commands.base import BaseCommand

class ValidateCommand(BaseCommand):
    name = "validate"
    help_text = "Validate an experiment definition"

    def execute(self, context: ExecutionContext, args: argparse.Namespace) -> int:
        raise NotImplementedError("P3.4")

COMMANDS["validate"] = ValidateCommand
```

**Required behavior:**
- Commands can be registered in any order (alphabetical iteration for help display).
- A missing `name` or `help_text` attribute is caught at registration time.
- The registry is readable by `main.py` for subparser creation and dispatch.

### 5. `BaseCommand` abstract class (`commands/base.py`)

```python
class BaseCommand:
    name: str
    help_text: str

    def configure_parser(self, parser: argparse.ArgumentParser) -> None:
        """Add command-specific arguments. Override in subclasses."""

    def execute(self, context: ExecutionContext, args: argparse.Namespace) -> int:
        """Execute the command. Returns an exit code."""
        raise NotImplementedError
```

**Required behavior:**
- `configure_parser()` is called during subparser creation so each command can add its own arguments.
- `execute()` receives the `ExecutionContext` and the parsed `Namespace`.

### 6. `ExecutionContext` value object (`commands/base.py`)

A frozen dataclass:

```python
@dataclass(frozen=True)
class ExecutionContext:
    verbose: bool = False
    debug: bool = False
    data_dir: str | None = None
```

**Required behavior:**
- Only globally-scoped CLI environment information.
- No persistence objects, no repositories, no application services.
- Created once in `main()` after argument parsing and passed to every command.

### 7. Exit code convention (`error_handling.py`)

```python
class ExitCode(IntEnum):
    SUCCESS = 0
    ERROR = 1
    VALIDATION_ERROR = 2
    INTERRUPTED = 130
```

**Required behavior:**
- `format_error(message: str, exit_code: ExitCode) -> str` — produces a consistently formatted error message.
- `handle_exception(exception: Exception) -> int` — maps common exceptions to exit codes and prints user-facing error text.
- KeyboardInterrupt is caught in `main()` and exits with code 130.
- The error formatting follows the patterns in the frozen CLI spec (see `CLI_INTERFACE_SPECIFICATION.md §5`).

## Acceptance Criteria

1. `sim-retire --help` displays usage, global options, and a command list.
2. `sim-retire --version` prints the package version.
3. `sim-retire UNKNOWN_COMMAND` exits with code 2 and an error message.
4. At least one `BaseCommand` subclass can be registered and dispatched through the framework.
5. `KeyboardInterrupt` during command execution exits with code 130.
6. `mypy src/cli/ --strict` reports 0 errors.
7. All existing tests (domain, research, optimization, infrastructure) continue passing.
