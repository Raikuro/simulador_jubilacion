## Executive Summary

P3.8 implements the `optimize` CLI command, which runs the frozen v0.3 `SWROptimizer` to find the maximum withdrawal rate satisfying a target success rate for a given experiment definition.

The optimize command is the first CLI command that:
- Exercises the **optimization layer** (v0.3 `SWROptimizer`)
- Runs **real simulations** with functional policies (not stubs)
- Requires an **Evaluator** bridge between the optimizer protocol and the execution engine
- Iterates a binary search, executing a full study per iteration

This package closes the P3.5 deferred item: *execution-grade policy implementations are delivered here.*

---

## Architectural Constraints

- **No frozen domain changes.** All code lives in the CLI layer (`src/cli/`) or extends the infrastructure persistence layer. No `engine.*`, `research.*`, or `research.optimization.*` files are modified — only their frozen public APIs are consumed.
- **SWROptimizer is frozen.** The `SWROptimizer` class at `src/research/optimization/swr_optimizer.py` is v0.3 frozen. Its `Evaluator` protocol, `OptimizerOutcome`, and `optimize()` signature must be consumed as-is. No modifications.
- **No frozen P3.4/P3.5/P3.6/P3.7 changes.** Do not modify `validate_command.py`, `run_command.py`, `list_command.py`, `export_command.py`, or their test files.
- **`cli.builders` is shared and evolvable.** Add new builder functions if needed; do not modify existing function signatures.
- **Concrete policy implementations are required.** P3.5 deferred execution-grade policies to the first package that needs them (P3.8). The optimize command runs real simulations and must subclass `AllocationPolicy`/`WithdrawalPolicy` with working `decide()` methods.
- **Shared policies module.** Real policy implementations live in a new shared `cli/policies.py` module (not private to the command), so that future commands (P3.9 `compare`, eventual full `run`) can reuse them.
- **Evaluator lives in the command.** The `_SWREvaluator` implementing the `SWROptimizer.Evaluator` protocol is private to `optimize_command.py`. It bridges the optimizer's binary search to the execution engine.
- **Persistence integration.** The optimize command persists the base experiment, the optimal plan, and its execution result via existing `SQLiteRepository` methods. No new tables required.
- **Exit codes:** 0 for success, 2 for validation error, 1 for execution error, 4 for database error, 130 for interruption.

## Architectural Analysis: Policy Gap

### Finding

**No production concrete `AllocationPolicy` or `WithdrawalPolicy` subclass exists anywhere in the codebase.** Every existing concrete implementation either:
- Raises `NotImplementedError` on `decide()` (codecs.py `_ConcreteAllocationPolicy`, `_ConcreteWithdrawalPolicy`)
- Returns empty stubs (run_command.py `_RunAllocationPolicy` with empty weights, `_RunWithdrawalPolicy` with zero withdrawal)
- Is a test-only dummy

### Resolution

P3.8 creates `src/cli/policies.py` containing these concrete, execution-grade policies:

| Class | YAML Type | Behavior |
|-------|-----------|----------|
| `ConstantAllocationPolicy` | `"ConstantAllocationPolicy"` | Returns fixed equity/bond split from `equity_ratio` parameter |
| `ConstantWithdrawalPolicy` | `"ConstantInflationAdjustedWithdrawalPolicy"` | Returns monthly withdrawal = portfolio_value × withdrawal_rate / 12 |

These policies live in the CLI layer (presentation layer) and subclass the frozen domain abstract classes. They are **shared** — available to future commands.

### Asset Class Convention

The domain dataset provides a single asset series. For allocation decisions:
- `equity_ratio` maps to `AssetClass(id="equity", ...)` with weight = `equity_ratio`
- The remainder `(1 - equity_ratio)` maps to `AssetClass(id="bond", ...)` with weight = `1 - equity_ratio`

This is consistent with the YAML format and the existing test/domain convention.

## What Must Exist

### 1. `cli/policies.py` — Shared concrete policy implementations

```python
"""Execution-grade policy implementations for CLI commands.

These subclass the frozen domain abstract policies (AllocationPolicy,
WithdrawalPolicy) and implement working decide() methods suitable for
real simulation execution.
"""

from decimal import Decimal

from engine.domain.model.allocation import AllocationTarget
from engine.domain.model.asset import AssetClass
from engine.domain.model.decision_context import DecisionContext
from engine.domain.model.money import Currency, Money
from engine.domain.policies.allocation_policy import AllocationPolicy
from engine.domain.policies.decisions import AllocationDecision, WithdrawalDecision
from engine.domain.policies.withdrawal_policy import WithdrawalPolicy


class ConstantAllocationPolicy(AllocationPolicy):
    """Fixed equity/bond split allocation policy.

    YAML type: "ConstantAllocationPolicy"
    YAML params: equity_ratio (Decimal, 0.0-1.0)

    The attribute name ``equity_allocation`` matches the key expected by
    ``AllocationPolicyCodec.dump()`` (see ``codecs.py`` line 103), enabling
    lossless round-trip persistence through the existing codec.
    """

    def __init__(self, equity_allocation: Decimal) -> None:
        self.equity_allocation = equity_allocation

    def decide(self, context: DecisionContext) -> AllocationDecision:
        equity = AssetClass(id="equity", name="Equity", description="")
        bond = AssetClass(id="bond", name="Bond", description="")
        return AllocationDecision(
            reason="ConstantAllocationPolicy",
            allocation_target=AllocationTarget(weights={
                equity: self.equity_allocation,
                bond: Decimal("1") - self.equity_allocation,
            }),
        )


class ConstantWithdrawalPolicy(WithdrawalPolicy):
    """Fixed-rate withdrawal policy.

    YAML type: "ConstantInflationAdjustedWithdrawalPolicy"
    YAML params: withdrawal_rate (Decimal, 0.0-1.0 annual)

    Withdrawal = portfolio_value * withdrawal_rate / 12 (monthly).
    Real amount uses the same value (inflation adjustment deferred).
    """

    def __init__(self, withdrawal_rate: Decimal) -> None:
        self.withdrawal_rate = withdrawal_rate

    def decide(self, context: DecisionContext) -> WithdrawalDecision:
        total = context.portfolio.total_value()
        monthly = total * self.withdrawal_rate / Decimal("12")
        return WithdrawalDecision(
            reason="ConstantWithdrawalPolicy",
            nominal_amount=Money(monthly, Currency.EUR),
            real_amount=Money(monthly, Currency.EUR),
        )
```

**Design notes:**
- `equity_ratio` is `Decimal`, not `float`, consistent with the domain's Decimal-only rule.
- `Months per year` is hardcoded as 12 (the domain's monthly-pipeline invariant).
- Inflation adjustment is deferred — `real_amount == nominal_amount` — consistent with the current domain model where inflation is modeled in market returns, not the withdrawal policy.
- These are **shared** — importable by any CLI command (optimize, compare, future run).
- The YAML `type` string is not stored on the class; mapping from YAML type string to class is the caller's responsibility.

### 2. `_SWREvaluator` — SWROptimizer Evaluator implementation

Create as a private class inside `src/cli/commands/optimize_command.py`:

```python
class _SWREvaluator:
    """Evaluator adapter: bridges SWROptimizer binary search to simulation execution.

    Implements the SWROptimizer.Evaluator protocol:
        evaluate(candidate: Decimal) -> EvaluationOutcome
    """

    def __init__(
        self,
        dataset: Dataset,
        cohorts: tuple[CohortSpecification, ...],
        param_configs: tuple[ParameterConfiguration, ...],
        allocation_policy: AllocationPolicy,
        capital: Money,
        target_success_rate: Decimal,
        workers: int,
    ) -> None:
        self._dataset = dataset
        self._cohorts = cohorts
        self._param_configs = param_configs
        self._allocation_policy = allocation_policy
        self._capital = capital
        self._target = target_success_rate
        self._workers = workers

    def evaluate(self, candidate: Decimal) -> EvaluationOutcome:
        # 1. Build withdrawal policy with candidate rate
        withdrawal_policy = ConstantWithdrawalPolicy(withdrawal_rate=candidate)

        # 2. Build experiment definition
        experiment_def = ExperimentDefinition(...)

        # 3. Build research plan
        plan = build_research_plan(
            experiment_def, self._cohorts, self._param_configs,
            self._allocation_policy, withdrawal_policy,
        )

        # 4. Execute plan
        if self._workers == 1:
            from infrastructure.execution.parallel_executor import sequential_execute
            result = sequential_execute(plan)
        else:
            from infrastructure.execution.parallel_executor import parallel_execute
            result = parallel_execute(plan, max_workers=self._workers)

        # 5. Compute success rate
        sim_results = result.results
        success_count = sum(1 for r in sim_results if r.statistics.success)
        total = len(sim_results)
        success_rate = Decimal(success_count) / Decimal(total)

        # 6. Return outcome
        return EvaluationOutcome(
            success=success_rate >= self._target,
            provenance={
                "candidate": str(candidate),
                "success_rate": str(success_rate),
                "success_count": success_count,
                "total_units": total,
            },
        )
```

### 3. `OptimizeCommand` class

Create `src/cli/commands/optimize_command.py`:

```python
class OptimizeCommand(BaseCommand):
    name = "optimize"
    help_text = "Find optimal withdrawal rate using SWROptimizer"

    def configure_parser(self, parser: argparse.ArgumentParser) -> None:
        parser.add_argument("study_file", type=str, help="Path to YAML experiment definition")
        parser.add_argument(
            "--target-success-rate", type=float, default=0.95,
            help="Target success rate (0.0-1.0)",
        )
        parser.add_argument(
            "--initial-capital", type=str, default="1000000",
            help="Starting portfolio value in EUR",
        )
        parser.add_argument(
            "--allocation-policy", type=str, required=True,
            help="Name of the allocation policy to optimize (must match YAML policy name)",
        )
        parser.add_argument(
            "--workers", type=int, default=1,
            help="Number of parallel workers",
        )
        parser.add_argument(
            "--tolerance", type=str, default="0.001",
            help="Withdrawal rate precision for binary search",
        )
        parser.add_argument(
            "--output-dir", type=str, default="./results/",
            help="Output directory",
        )

    def execute(self, context: ExecutionContext, args: argparse.Namespace) -> int:
        # 0. Validate --target-success-rate range
        # 1. Parse and validate YAML
        # 2. Select allocation policy by name (--allocation-policy)
        # 3. Build cohorts, parameters from YAML
        # 4. Build _SWREvaluator
        # 5. Run SWROptimizer.optimize()
        # 6. Print iteration progress
        # 7. Print final optimal rate and summary
        # 8. Persist experiment, optimal plan, and execution result to SQLite
        # 9. Exit 0
```

**Argument parsing details:**
- `--initial-capital` is `str` (parsed to `Decimal` internally) to preserve precision
- `--tolerance` is `str` (parsed to `Decimal` internally)
- `--target-success-rate` is `float` (display-friendly; converted to `Decimal` for comparison)
- `--allocation-policy` is `required=True` (the command needs exactly one policy to optimize)
- `--target-success-rate` **must be validated** in `execute()` before any other work. If the value is outside `[0.0, 1.0]`, print an error and return `ExitCode.VALIDATION_ERROR` (2). This is a CLI-level argument validation, not a domain-level check.

### 4. Policy selection from YAML

The YAML `allocation_policies` section is a list of dicts, each with a `name` key. The `--allocation-policy` argument selects by name:

```python
def _select_allocation_policy(
    policies_data: list[dict[str, Any]], policy_name: str
) -> AllocationPolicy:
    """Find the YAML policy entry matching *policy_name* and build a
    ConstantAllocationPolicy from its parameters.

    The YAML key ``equity_ratio`` maps to the constructor parameter
    ``equity_allocation`` for codec compatibility (see ``codecs.py``).
    """
    for entry in policies_data:
        if entry.get("name") == policy_name:
            ratio = Decimal(str(entry.get("equity_ratio", 0.75)))
            return ConstantAllocationPolicy(equity_allocation=ratio)
    raise ValueError(f"Allocation policy '{policy_name}' not found in YAML")
```

**Validation rules:**
- If `--allocation-policy` does not match any YAML policy name, exit code 2 with descriptive error.
- If `equity_ratio` is missing from the matched entry, default to `0.75`.
- Only `ConstantAllocationPolicy` type is supported in v0.4. If the YAML entry has a `type` other than `"ConstantAllocationPolicy"`, emit a warning and proceed with `equity_ratio` if present.

### 7. Persistence

The optimize command persists three artifacts using existing `SQLiteRepository` methods:

1. **Base experiment definition** — via `repo.save_experiment()` (stores the experiment metadata, cohorts, policies)
2. **Optimal plan** — via `repo.save_plan()` (stores the plan built with the optimal withdrawal rate)
3. **Optimal execution result** — via `repo.save_execution_result()` (stores the results of the final/optimal iteration)

The `OptimizerOutcome` metadata (candidate values, iterations count) is printed to stdout. Full auditability is preserved because the persisted experiment, optimal plan, and execution result allow reproducing the optimal iteration. For file-based export of results, users should use `sim-retire export` (P3.7).

**Database path resolution** follows the same pattern as export/run commands:

```python
db_path = str(Path("~/.sim-retire/studies.db").expanduser())
```

## Architecture Review: Key Decisions

### Decision 1: Evaluator as a private class
The `_SWREvaluator` lives in `optimize_command.py` (not a separate module). It is the only consumer of the SWROptimizer protocol in v0.4 and has no reuse value outside the optimize command. Making it private keeps the CLI package flat.

### Decision 2: Shared policies module (`cli/policies.py`)
Concrete policy implementations are extracted into a shared module (not private to optimize_command.py) because:
- P3.9 (`compare` command) and the eventual full-run path need them.
- `cli/builders.py` follows the same shared-module pattern.
- Test concerns are separated (`test_policies.py` is independent of `test_optimize_command.py`).

### Decision 3: No new database table for optimizer metadata
The `OptimizerOutcome` (iterations, candidate history) is printed but not persisted. The base experiment + optimal plan + execution result are sufficient to reproduce the optimal iteration. Adding a dedicated `optimization_results` table would increase schema complexity without proportional benefit. If audit trails require iteration-level provenance in the future, an ADR should precede that work.

### Decision 4: Binary search domain bounds
The default domain for the SWROptimizer binary search is `[0.0, 0.10]` (0% to 10% withdrawal rate). This covers the realistic range for SWR studies. The bounds are not configurable in P3.8; if needed, a future package can add `--domain-min` / `--domain-max` options.

### Decision 5: Parallel execution within evaluator
The evaluator accepts a `workers` parameter and uses `sequential_execute` / `parallel_execute` for each binary search iteration. Each iteration is a full study execution. This is computationally expensive but architecturally correct — the binary search operates on study-level outcomes, not per-simulation outcomes.

### Decision 6: No `--resume` for optimize
The optimize command does not support `--resume`. Each invocation is independent. Resume capability requires persistence of iteration state, which is out of scope for P3.8.

| D2 | **Codec load-side policies are non-functional.** `AllocationPolicyCodec.load()` and `WithdrawalPolicyCodec.load()` return `_ConcreteAllocationPolicy` / `_ConcreteWithdrawalPolicy` which raise `NotImplementedError` on `decide()`.
