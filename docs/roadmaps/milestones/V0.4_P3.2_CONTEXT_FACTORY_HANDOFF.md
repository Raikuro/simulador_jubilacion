## Executive Summary

P3.2 is the second implementation package of Phase 3. It completes the **persistence infrastructure** by providing production wiring and file-based dataset resolution. It is **not** an application layer — it contains no use-case orchestration.

What it provides:

1. **File-based dataset loading** — A concrete mechanism for `DefaultDatasetResolver` to load `Dataset` objects from JSON files on disk, addressing P3.1 technical debt item TD-2.

2. **`create_persistence_context()`** — A single-responsibility factory that produces a fully wired `PersistenceReconstructionContext`. CLI commands and downstream code call this factory; they never construct or configure codecs directly.

Downstream packages (P3.3–P3.10) receive a ready-to-use context from this factory. The true Application Layer — responsible for use-case orchestration (`study_runner`, `optimization_runner`, `comparison_runner`) — begins after P3.2 in a separate set of packages.

---

## Architectural Constraints

- **No frozen domain changes.** All code lives in the infrastructure layer (`src/infrastructure/persistence/`). No `engine.*` or `research.*` files are modified.
- **No behavioral changes to `SQLiteRepository`.** The repository receives its context as before.
- **No modification to P3.1 protocol implementations.** The `DefaultDatasetResolver` gets a new factory classmethod, not a changed interface. The codecs (`AllocationPolicyCodec`, `WithdrawalPolicyCodec`, `SimulationResultCodec`) are unchanged.
- **Factory has a single responsibility.** `create_persistence_context()` constructs a `PersistenceReconstructionContext` — nothing more. It is not a generic service locator or dependency container. Future wiring needs introduce separate factories.
- **JSON format is an infrastructure implementation detail.** Higher layers interact with `DatasetResolver` → `Dataset` and must never depend on the JSON file format. Future resolver implementations (database, binary, remote) must be replaceable without changing consumers.
- **No CLI code.** P3.2 is infrastructure wiring, not user-facing commands.

## What Must Exist

### 1. Dataset JSON file format & loader

Define a JSON format for serializing a `Dataset` to disk and loading it back. The format preserves all field types losslessly:

| Field | JSON Type | Notes |
|-------|-----------|-------|
| `version` | string | Dataset identifier (e.g., `"ACWI_EUR_2024"`) |
| `frequency` | string | e.g., `"monthly"` |
| `snapshots` | array of objects | Ordered by date ascending |
| `snapshots[].date` | string | ISO 8601 `YYYY-MM-DD` |
| `snapshots[].inflation` | string | Decimal stored as string |
| `snapshots[].inflation_cumulative` | string | Decimal stored as string |
| `snapshots[].is_ath` | boolean | |
| `snapshots[].is_underwater` | boolean | |
| `snapshots[].running_ath` | string | Decimal stored as string |
| `snapshots[].index_levels` | object | Keys = asset class IDs, values = Decimal strings |

**Required behaviors:**
- Load a `Dataset` from a single JSON file.
- Load all `Dataset` files from a directory (each `.json` file is one dataset; the filename stem is the identifier).
- Raise `StudyNotFoundError` (a `RepositoryError` subclass) if a file does not exist or cannot be parsed.
- The JSON format is **private to the infrastructure layer**. It is not a public API contract.

### 2. `DefaultDatasetResolver` file-backed construction

Add a `from_data_dir` classmethod to `DefaultDatasetResolver`:

```python
resolver = DefaultDatasetResolver.from_data_dir("/path/to/datasets")
resolver.resolve("ACWI_EUR_2024")  # loads /path/to/datasets/ACWI_EUR_2024.json
```

The existing `__init__(datasets=...)` constructor remains unchanged for backward compatibility.

### 3. `create_persistence_context` factory

A module-level function with a single responsibility: construct a correctly wired `PersistenceReconstructionContext`.

```python
def create_persistence_context(data_dir: str | None = None) -> PersistenceReconstructionContext
```

The factory:
- Creates a `DefaultDatasetResolver` (from `data_dir` if provided, otherwise empty).
- Creates `AllocationPolicyCodec`, `WithdrawalPolicyCodec`, `SimulationResultCodec`.
- Returns `PersistenceReconstructionContext` with all three wired in.

**Required behavior:** `create_persistence_context()` with no arguments produces a valid context with an empty resolver — all codecs work, but dataset resolution raises `StudyNotFoundError`.

### 4. Public API exports

Add `create_persistence_context` to `src/infrastructure/persistence/__init__.py`.

## Tests

| Behavior | Description |
|----------|-------------|
| Dataset JSON file write/read | Write `Dataset` to a JSON file, read it back — identical fields |
| Dataset file not found | Missing file raises `StudyNotFoundError` |
| Dataset directory loading | `DefaultDatasetResolver.from_data_dir()` loads all `.json` files |
| Unknown identifier after dir load | Raises `RepositoryError` |
| Factory returns valid context | `create_persistence_context()` returns a valid `PersistenceReconstructionContext` |
| Factory with data dir | Context resolver resolves known identifiers |
| Factory without data dir | Empty resolver; resolving raises `StudyNotFoundError` |
| Existing tests unchanged | All P3.1 codec + persistence tests still pass |
