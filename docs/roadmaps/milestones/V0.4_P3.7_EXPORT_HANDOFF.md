## Executive Summary

P3.7 implements the `export` CLI command, which retrieves stored study results from the SQLite database and writes them to a file in CSV or JSON format.

The export command is a read-only operation on the persistence layer. It validates nothing, executes nothing, and modifies nothing. It reads completed execution results and transforms them into flat tabular rows (CSV) or structured metadata + rows (JSON).

---

## Architectural Constraints

- **No frozen domain changes.** All new command code lives in the CLI layer (`src/cli/commands/`). No `engine.*` or `research.*` files are modified. The `SQLiteRepository` is extended with `get_export_data()`, `find_plan_by_experiment()`, and module-level helper functions as specified in §2.
- **No frozen P3.4/P3.6 changes.** Do not modify `validate_command.py` (P3.4 frozen), `run_command.py` (P3.5 frozen), `list_command.py` (P3.6 frozen), or their test files.
- **Repository-driven data access.** All database access goes through `SQLiteRepository.get_export_data()`. No raw SQL in the CLI layer.
- **No PersistenceReconstructionContext required.** The export path produces flat dicts, not domain objects, and does not require codec registration or reconstruction context.
- **File output is a CLI responsibility.** Output directory creation, file naming, format writing, and I/O error handling are owned by the CLI layer.
- **Exit codes:** 0 for success, 1 for logical errors (no results), 4 for database errors, 130 for interruption.

### 3. Output format specifications

**CSV format:**

```
cohort_start_date,equity_allocation,month_index,portfolio_value,withdrawal,success
2020-01-01,0.75,0,1000000.00,3333.33,1
```

**JSON full format:**

```json
{
  "study_id": "study-abc123",
  "name": "Export Test Study",
  "revision": "1.0",
  "created_at": "2026-07-25T12:00:00Z",
  "executed_at": "2026-07-25T13:00:00Z",
  "duration_seconds": 120.5,
  "success_rate": 0.5,
  "total_units": 2,
  "success_count": 1,
  "failure_count": 1,
  "parameter_keys": ["equity_allocation"],
  "rows": [
    {
      "cohort_start_date": "2020-01-01",
      "equity_allocation": "0.75",
      "month_index": 0,
      "portfolio_value": "1000000000",
      "withdrawal": "3333.33",
      "success": 1
    }
  ]
}
```

**JSON summary format** — same as full but without the `rows` array.

### 4. COMMANDS registration

In `src/cli/commands/__init__.py`, add:

```python
from cli.commands.export_command import ExportCommand
COMMANDS["export"] = ExportCommand
```

### 5. Error handling

| Condition | Exit Code | Behavior |
|-----------|-----------|----------|
| Database unreachable | 4 (DATABASE_ERROR) | Print error, return DATABASE_ERROR |
| No study found | 1 (ERROR) | Print "No completed results found" |
| No data rows | 1 (ERROR) | Print "No data rows found" |
| File write failure (OSError) | 1 (ERROR) | Print contextual I/O error message |
| Aggregated metrics (falls back to full) | 0 (SUCCESS) | Print notice that aggregated falls back to full |
| Successful export | 0 (SUCCESS) | Print summary with format, metrics, output path, row count, file size |

## Tests

| Behavior | Description |
|----------|-------------|
| Default CSV export | Exports study to CSV file, exits 0 |
| JSON full export | Exports study to JSON with all fields, exits 0 |
| JSON summary export | Exports study metadata without rows, exits 0 |

## Acceptance Criteria

1. `sim-retire export STUDY_ID` writes CSV file and exits 0.
2. `sim-retire export STUDY_ID --format json` writes valid JSON and exits 0.
3. `sim-retire export STUDY_ID --metrics summary` writes JSON without rows.
4. `sim-retire export STUDY_ID --output PATH` writes to custom path.
5. `sim-retire export STUDY_ID --help` displays export-specific help.
6. `sim-retire export nonexistent` exits 1 with error message.
7. `sim-retire export STUDY_ID` on unreachable database exits 4 with error message.
8. `mypy src/cli/ --strict` reports 0 errors.
9. All existing tests continue passing.
