## Executive Summary

P3.4 is the fourth implementation package of Phase 3. It implements the `validate` CLI command, which parses a YAML experiment definition file and validates it without executing any simulations. This is the first command implementation in the CLI layer.

The validate command exercises the complete CLI framework (P3.3): BaseCommand subclass, configure_parser, execute, COMMANDS registration, and exit code conventions. It validates the entire experiment definition pipeline: YAML parsing, ExperimentDefinition construction, ResearchPlan creation, and component-level validation.

---

## Architectural Constraints

- **No frozen domain changes.** All code lives in the CLI layer (`src/cli/commands/`). No `engine.*` or `research.*` files are modified; only their frozen public APIs are consumed.
- **Validate does not execute simulations.** It parses, constructs, and validates. No simulation runs, no persistence writes.
- **No output formatters.** Validation output is printed directly to stdout (text report). Table formatting, CSV, and JSON export are deferred to later packages.
- **COMMANDS registration.** The `ValidateCommand` class must be registered in `src/cli/commands/__init__.py` via `COMMANDS["validate"] = ValidateCommand`.
- **Exit codes match the P3.3 framework:** 0 for success, 2 for validation failure, 1 for execution errors.

## What Must Exist

### 1. ValidateCommand class

Create `src/cli/commands/validate_command.py`:

```python
class ValidateCommand(BaseCommand):
    name = "validate"
    help_text = "Validate an experiment definition"

    def configure_parser(self, parser: argparse.ArgumentParser) -> None:
        parser.add_argument("study_file", type=str, help="Path to YAML experiment definition")

    def execute(self, context: ExecutionContext, args: argparse.Namespace) -> int:
        # 1. Parse YAML file
        # 2. Construct ExperimentDefinition
        # 3. Create ResearchPlan
        # 4. Validate all components
        # 5. Print validation report
        # 6. Return 0 if valid, 2 if invalid
```

### 2. YAML parsing

Parse the YAML experiment definition file. The format is defined in CLI_INTERFACE_SPECIFICATION.md §7.1.

**Required behaviors:**
- Parse YAML from a file path (string or Path)
- Raise `ValidationError` (exit code 2) if the file does not exist
- Raise `ValidationError` (exit code 2) if the YAML is malformed
- Return a dict-like structure for ExperimentDefinition construction

**Note:** YAML parsing (`pyyaml`) is an external dependency. Add it to `pyproject.toml` under `[project.optional-dependencies] dev` or `[project.dependencies]`. Since `pyyaml` is a standard library dependency (stdlib equivalent), the architecture document lists it as allowed in the infrastructure layer.

### 3. ExperimentDefinition construction

Construct an `ExperimentDefinition` from parsed YAML data using the frozen public API from `research.experiment_definition`.

**Required validations:**
- Dataset identifier must be resolvable via `DefaultDatasetResolver`
- Cohort specification must be valid (dates in range, window positive)
- Parameter axes must have valid ranges
- Allocation policies must be constructible
- Withdrawal policy must be constructible

### 4. ResearchPlan creation

Create a `ResearchPlan` from the constructed `ExperimentDefinition`.

**Required validations:**
- Plan generates simulation units without errors
- No duplicate simulation units
- Total unit count is reasonable (warning if > 10000)

### 5. Validation output

Print a structured validation report to stdout following the format in CLI_INTERFACE_SPECIFICATION.md §3.3 Example Output:

- Section for ExperimentDefinition validity
- Section for cohort validity (count, range, type)
- Section for parameter validity (count, ranges)
- Section for policy validity (allocation + withdrawal)
- Section for plan validity (total units, uniqueness)
- Final verdict: PASSED or FAILED

### 6. Error handling

| Condition | Exit Code | Behavior |
|-----------|-----------|----------|
| File not found | 2 | Print error, return VALIDATION_ERROR |
| Invalid YAML | 2 | Print parse error with line number |
| Invalid experiment definition | 2 | Print validation errors |
| Valid experiment definition | 0 | Print success report |
| Unexpected exception | 1 | Print error, return ERROR |

### 7. COMMANDS registration

In `src/cli/commands/__init__.py`, add:
```python
from cli.commands.validate_command import ValidateCommand
COMMANDS["validate"] = ValidateCommand
```
